## 3-1. A と B の分け方 → A は要る

- B-2 の対照（root から門番の `XPC_SERVICE_NAME` が見える）でわかるのは、「root は launchd の Go のバイナリの環境変数を読める」ことまで
- 環境変数が隠れるかは、実験1のとおりバイナリの出自（Apple の署名か、adhoc か）でも変わった。B-3 で「本人の uid からは合言葉 0」が出ても、別ユーザーだからかバイナリの性質かを分けるには、adhoc の Go のバイナリを `_monban` で動かす A が要る。本物の合言葉を使わず安く済む
- `sudo -u _monban` で起こすのは、この問いには問題にならない。効くのは「相手のプロセスの uid・読む側の uid・バイナリの署名」。launchd を通るかどうかは環境変数の中身（`XPC_*`）の話で、そちらは B-2 が受け持つ

## 3-2. `bws` の子の捕まえ方 → 見張りでよい。捕まえた回を複数に

- 本番の `bws` と門番に手を入れない前提なら、`pgrep` の見張りと「root の行が 0 ならやり直す」が妥当
- 足すなら、捕まえた回を1回で終わらせず、取り出しを2〜3回繰り返して、全部で同じ数が出ること。取り逃しは起きても、ごまかしにはならない形

## 3-3. root の出力をシェルの変数に一瞬持つ → 許せる

- 条件（エージェントのいないウィンドウ、画面・ファイル・履歴に出さない、数だけ出して `unset`）を今の案は満たしている
- B-2 のように `ps … | grep -c` とパイプで数える形は変数にすら残らないので、書けるところではそちらを優先する

## 3-4. `ps` 以外で足すもの → 合言葉のファイルの `cat` は足す

- `cat /var/db/monban/secret/token` が「Permission denied」になるかは、`ps` とは別の層（ファイルの権限）の確かめで、30秒で済む
- `launchctl print` は、引数に秘密が入っていないことを1回目で見る程度。必須ではない

## 3-5. 確かめた後の本物の合言葉 → そのまま動かしてよい

- 届くのが `MONBAN_TEST`（値はダミー）だけなら、失効させる損のほうが大きい。本番の形を動かし続けるのが10段目の意味でもある
- 区切りは「最初の本物の秘密を入れるとき」。そのときに新しい合言葉に替える

## 3-6. 「これで防げないこと」と README → 4つで言い過ぎはない

- 特に「1回の瞬間の確かめで、ずっと見えないことの証明ではない」が効いている
- README には、10段目が通ったら「本番の形（launchd・別ユーザー）で確かめた」と書いてよい。ただし無条件の「見えない」ではなく、いつ・どの形で・root の対照つきで確かめた結果として書く。限界の節が隣にある今の README の形なら問題ない
