## 1. 実験の結果（前回「表が埋まったら教えて」と言われた件）

2026-11-10、macOS（Darwin 25.5.0）、人のターミナルで行った。

**実験1：別ユーザーのプロセスの環境変数は `ps eww` で見えないか**

- 見えなかった。前回の答えと一致した
  - 自分のユーザーのプロセス（対照）では見えた
  - `nobody` のプロセスでは、行は `ps` に出たが、目印は見えなかった
  - root からは見えた。目印が入っていたことは、これで確かめた
- 途中でわかったこと：OS に入っているプログラム（`/bin/sleep`、zsh）は、同じユーザーからでも環境変数が見えなかった
  - `/bin/sleep` を複製して自分で署名し直す（`codesign -f -s -`）と見えた
  - どの条件で隠れるのかは確かめていない
- 本番の形（launchd のデーモン、`_monban`、`bws`）では、まだ試していない

**実験2：`bws secret get` の1回の時間**（bws v2.1.0、Wi-Fi）

| 測ったもの | real（秒） |
|---|---|
| `bws --version`（3回） | 0.01, 0.00, 0.00 |
| `get` 冷えた状態（状態ファイルを消して1回） | 1.11 |
| `get` 温まった状態（5回） | 0.50, 0.47, 0.47, 0.47, 0.68 |

- 判断：毎回子プロセスで呼ぶ形のままにする。`bws` を常駐させる形は考えない

## 3. 聞きたいこと

1. **`_monban` のキーチェーン**
   - `_monban` はログインしないユーザー。その launchd デーモンから、キーチェーンの項目を読めるか
   - 読めないなら、合言葉をどこに置くのがよいか。考えている代わりは2つ
     - `_monban` だけが読めるファイル（0600）
     - System キーチェーン
2. **Pushover の承認**
   - Pushover で「承認」と「拒否」の両方を門番に返せるか
   - 緊急の優先度の受領確認は「見た」しか返さないように思う
   - 返せないなら、v1 の承認はどう組むのがよいか（例：通知は Pushover、承認はターミナルのコマンド、など）
3. **ソケットの相手の確かめ方**
   - Go から `LOCAL_PEERCRED`（`getpeereid`）で uid を取る形で足りるか
   - ソケットの権限は、`_monban` の持ち物にして、使う人のグループにだけ書き込みを許す形を考えている。穴はあるか
4. **注入の値の通り道**
   - 4段目では、値がデーモンからソケットで `monban run` に渡る。`run` は値を環境変数に入れて `exec` する
   - この間、値はユーザーの uid のプロセスの中にある
   - この形でよいか。もっとよい渡し方はあるか
5. **順番**：9段の順番で、入れ替えたほうがよいところや、抜けている段はあるか
