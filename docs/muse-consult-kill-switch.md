## 1. 作ったもの

- `monban stop` は、ソケットで門番に `{"op":"kill"}` を送る。承認の番号は要らない（止める向きは、間違って押しても秘密は出ない）。持ち主の uid の照合は、ほかの要求と同じ
- 門番は、止める要求の行（`op` は `kill`。門番が書く停止の行の `stop` とは分ける）を書いて `OK <ID>` を返し、止め始める。ログに書けなくても止める（止める向きは安全な側）
- 止め始めたら：
  - 新しい接続を受けない（待ち受けを閉じる）。閉じる直前に繋いだ要求は、中身を見ずに断る
  - 承認待ちの要求は断る（6段目の「門番を止めた」）
  - 取り出し中の `bws` は取り消す（kill）。取れていても渡さない。`bws` が子のプロセスを残して出力を握っていても、2秒で待つのをやめる
  - 「渡した」の行を書く前に止める要求が来れば渡さない。後に来たら、もう渡している
  - 動いている接続が全部終わってから停止の行を書き、ソケットを消す。停止の行には何で止めたか（`monban stop、uid … pid …` か `合図 terminated`）を書く
- `monban stop` は、ソケットが消えるのを見て（45秒まで待つ）「止まった」と出し、失効の手順を出す
- 門番に繋げないとき（もう止まっている・固まっている・置き場が違う）も、失効の手順は出す。終了コードは1
- 同じ uid のエージェントも `monban stop` を打てる（1の答えのとおり、許す）

## 2. 確かめたこと（自分の uid・偽の合言葉）

- 単体の試験（`go test -race`）：
  - 止める要求で、待ち受けを閉じ、`bws` の取り消しの合図が出て、ログに止める要求の行と停止の行が入る。2回止めても落ちず、最初の理由が残る
  - 持ち主ではない uid の止める要求は断る（止まらない）
  - 止め始めた後に届いた要求は、許可リストより前で断る
  - 取り出し中に止める：偽の `bws`（5秒待ってから値を返す）で、止めてから断るまで3秒以内。ログに「渡した」も値もない。2秒で待つのをやめる直しを外すと、子の `sleep` が出力を握ったままで4.5秒待たされ、試験が落ちた（値は渡さなかった）
- 門番を動かして（`-pushover` なし）：起動して stop、承認待ちのまま stop（`run` は `NG`）、止まっているときに stop（手順を出して終了コード1）、SIGTERM。9行の連鎖が `verify-log` で合った

## 3. 聞きたいこと：失効の手順の文面

`monban stop` が出す文（そのまま）：

```
門番を止めただけでは、合言葉（アクセストークン）は生きている。合言葉を止めるには：
  1. Bitwarden のウェブの画面に入り、組織の Secrets Manager を開く
  2. 「Machine accounts」→ 門番のマシンアカウント →「Access tokens」タブ
  3. 合言葉のメニュー →「Revoke access token」
失効させても、すでにログイン済みのところは最大1時間、読み続けられる（即時の遮断ではない）。
合言葉が漏れたと思うなら、Secrets Manager の中の秘密そのもの（API キーなど）も、それぞれのサービスで取り替える。
門番をまた動かすときは、新しい合言葉を作って、合言葉のファイルを入れ替えてから起動する。
```

止まったときは、その前に次の1行が出る：

```
門番は止まった（新しい要求は受けない。承認待ちの要求は断った。まだ渡していない値は渡していない）
```

こちらで気になっている点：

- 「まだ渡していない値は渡していない」は、止める前に渡した値（`run` が受け取り、注入先のコマンドが使っている値）は取り戻せない、とは書いていない。足すべきか
- 「最大1時間」の主語：Bitwarden の文書は、失効しても、すでにログイン済みのマシンは最大1時間読めると書いている。門番の `bws` のほかに、合言葉を盗んだ誰かが先にログインしていれば、その人も最大1時間読める、という読みでよいか
- 最後の行は「必ず新しい合言葉に替える」と読める。漏れの疑いがなく、ただ止めただけのとき（試しや、念のため）にも替えるのは重いか。替えずに起動し直す道を書くべきか（9段目の「止めた印」の解除と合わせて）
- ウェブの画面の文字（「Machine accounts」など）は、試用のときに見た英語の表示のまま

## 4. 2の答え（止めた印）を9段目でどう作るつもりか

- 門番の状態のディレクトリ（本番は `_monban` の 0700 の中）に、`monban stop` で止めたときだけ印のファイルを置く（合図で止めたとき・落ちたときは置かない）
- 印があれば起動しない。起動の失敗のメッセージに、理由（いつ・誰の uid で止めたか）と解除の方法（`sudo rm <印>`）を出す
- launchd は `KeepAlive` の `SuccessfulExit: false`（落ちたら起き直し、止めたら止まる）と併用する
- 8段目では作らない（状態のディレクトリが決まるのが9段目）

- 「見せない」の効果を盛らない
