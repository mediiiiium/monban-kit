# v1.5 を本番の形に入れる（出力から秘密の値を伏せる）

作成日: 2026-11-13
作ったもの：[v1-plan.md](v1-plan.md) の「v1.5：出力から秘密の値を伏せる」
前提：本番の形（`_monban` の launchd のデーモン、`scripts/install.sh` で入れたもの）が動いていて、`MONBAN_TEST` と `PUSHOVER_TOKEN` が通る（[first-real-secret.md](first-real-secret.md)）

## やること

門番のバイナリ（`/usr/local/libexec/monban/monban`）だけを入れ替える。門番も `monban run` も同じファイルなので（`/usr/local/bin/monban` はそこへのリンク）、1回で両方が v1.5 になる。

- `scripts/uninstall.sh` と `scripts/install.sh` はやり直さない。合言葉・Pushover のキー・許可リスト・ログ・番号の記録はそのまま使う
- 止めるのは `launchctl bootout`（合図で止める）。`monban stop` で止めると止めた印が残り、印を消すまで起動しなくなる
- 人のターミナルで、エージェントのいないウィンドウで行う。sudo はエージェントに打たせない

## 決まり

- 合言葉や本物のパスワードは、このリポジトリにも会話にも出さない
- 「見せない」の効果を盛らない

## 1. 組み立てる

リポジトリで（sudo は要らない）：

```sh
cd ~/monban-kit
git log --oneline -1
go test -race ./...
go build -o /tmp/monban-v15 ./cmd/monban
```

- `git log` の先頭が v1.5 のコミット（`ccfb4c4` 以降）であること
- 試験が `ok` で終わること

## 2. 入れ替える

```sh
sudo launchctl bootout system/io.github.mediiiiium.monban
# bootout は止まりきるのを待たずに戻る。止まりきる前に bootstrap すると「Bootstrap failed: 5: Input/output error」になる
while sudo launchctl print system/io.github.mediiiiium.monban >/dev/null 2>&1; do sleep 1; done; echo "止まった"
sudo /usr/bin/install -o root -g wheel -m 0755 /tmp/monban-v15 /usr/local/libexec/monban/monban
cmp /tmp/monban-v15 /usr/local/libexec/monban/monban && echo "同じ中身"
ls -l /usr/local/libexec/monban/monban
sudo launchctl bootstrap system /Library/LaunchDaemons/io.github.mediiiiium.monban.plist
sudo launchctl print system/io.github.mediiiiium.monban | grep -E "state|pid"
rm /tmp/monban-v15
```

見ること：

- 「同じ中身」が出る。持ち主は `root wheel`、モードは `-rwxr-xr-x`
- `state = running` で、pid が出る
- 起動しないときは、門番の画面のログ（`sudo tail /var/log/monban/daemon.log`）の最後の行に理由がある

## 3. `MONBAN_TEST` で伏せるのを確かめる

ウィンドウ1：

```sh
monban run MONBAN_TEST -- /usr/bin/printenv MONBAN_TEST; echo "exit=$?"
```

ウィンドウ2（Pushover に届いた番号で）：

```sh
monban approve <番号>
```

見ること（v1 では値がそのまま出ていた。v1.5 では出ないのが正しい）：

- ウィンドウ1に `【monban: 伏せた】` と `【monban run】出力から秘密の値を 1 か所伏せた` が出て、`exit=0`
- ダミーの値そのものは出ない

`門番に断られた` と出たら、`sudo tail -3 /var/log/monban/audit.log` の最後の行の `result` を見る：

- `値が短すぎて出力から伏せられない（8バイト未満）`：ダミーの値が8バイトより短い。Bitwarden のウェブの画面で、`MONBAN_TEST` の値を8文字以上のダミーに替えてから、3をやり直す（名前と ID は替えない。許可リストはそのまま）
- `値が伏せた印と重なるので出力から伏せられない`：ダミーの値に `【` か `】` が入っている。同じく値を替える

## 4. 本物の秘密を通す

ウィンドウ1（ユーザーキーは画面にも履歴にも出さない）：

```sh
read -rs 'PU?Pushover のユーザーキー: '; echo
```

```sh
PUSHOVER_USER=$PU monban run PUSHOVER_TOKEN -- /usr/local/libexec/monban-cmds/pushover-notify "v1.5 の門番を通った" "monban"; echo "exit=$?"
unset PU
```

ウィンドウ2：承認の通知に出た番号で承認する。

```sh
monban approve <番号>
```

見ること：

- ウィンドウ1に「送った」と request の ID が出て、`exit=0`。トークンは出ない
- `【monban run】…伏せた` の行は出ない（`pushover-notify` はトークンを出さない作りなので、伏せるものがない）
- スマホに「v1.5 の門番を通った」が届く（`monban-local` から）

これからの確かめは、値が見えるかどうかではなく、次の組み合わせで見る：

- 伏せる側：`【monban run】…伏せた` の行が出ること（`MONBAN_TEST` を `printenv` で）
- 通った側：ログの「渡した」と、スマホに通知が届くこと（`PUSHOVER_TOKEN`）

## 5. 記録を確かめて片づける

```sh
monban verify-log /var/log/monban/audit.log
sudo tail -6 /var/log/monban/audit.log
sudo -k
```

- 連鎖が合う。入れ替えの前の停止の行（`合図 terminated`）と、起動の行がある
- 最後の数行に `MONBAN_TEST` と `PUSHOVER_TOKEN` の要求・承認・渡した記録がある。値は書かれていない
- 終わったら、`README.md` の「いまの段階」と、この下の「結果」を書く

## 結果

2026-11-13、人のターミナルで行った。

- 1：`910600a` で、試験は `ok`
- 2：入れ替えは「同じ中身」、`root wheel` の `-rwxr-xr-x`。続けて打った `bootstrap` は `Bootstrap failed: 5: Input/output error` で失敗した。古い門番がまだ止まりかけ（`state = SIGTERMed`）だった。止まったのを確かめてから（`Could not find service`、daemon.log に「止めた（合図 terminated）」、ログの seq 46）`bootstrap` し直すと、`state = running` で新しい pid になった。手順の2に、止まりきるのを待つ1行を足した
- 3：`MONBAN_TEST` を `printenv` で通すと、`【monban: 伏せた】` と `【monban run】出力から秘密の値を 1 か所伏せた` が出て、`exit=0`。ダミーの値は出なかった。断られなかったので、ダミーは8バイト以上だった
- 4：`PUSHOVER_TOKEN` を通すと、「送った」と request の ID が出て、`exit=0`。トークンも「伏せた」の行も出なかった。スマホに「v1.5 の門番を通った」が届いた
  - つまずき：ユーザーキーの `read` と続きのコマンドを、説明の文ごと1回で貼った。説明の文は zsh に「command not found」と言われただけで、`read` はユーザーキーを受け取れていた（Pushover が受け付けた）。`read` の行は1行だけで打つほうが確か
- 5：連鎖は53行で合った。seq 50 が `MONBAN_TEST`、seq 53 が `PUSHOVER_TOKEN` の「渡した」で、どちらも承認の画面と承認の行の後にある。値はどの行にも書かれていない
