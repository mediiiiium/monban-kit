## 決まり

- 合言葉や本物のパスワードは、このリポジトリにも会話にも出さない。試すときの秘密はダミーの `MONBAN_TEST` だけ
- 1段ずつ作り、段ごとに「動いた」を人の目で確かめてから次へ進む
- 「見せない」の効果を盛らない。段ごとに「これで防げないこと」も書く

## 決めたこと（Muse と相談して）

- **合言葉の置き場**：キーチェーンではなく、`_monban` だけが入れる 0700 のディレクトリの中の、`_monban` の持ち物で 0600 のファイル。デーモンは起動時に1回だけ読む。電源が切れているときの暗号化は FileVault に任せる。System キーチェーンは、署名が固まってから考え直す
- **承認**：Pushover は知らせるだけ（リクエストの ID と「どのエージェントが・どの秘密を・どのコマンドに」）。判断はターミナルの `monban approve <ID>` / `monban deny <ID>`
- **ソケット**：
  - ディレクトリは `_monban` の持ち物、使う人だけの専用グループ、0750。ソケットは同じ持ち主とグループで 0660
  - ディレクトリにグループの書き込みを付けない（付けると、ソケットを偽物に差し替えられる）
  - デーモンは、繋いできた uid が設定の持ち主の uid と一致するかも照合する
  - 起動時に持ち主とモードを調べ、違えば起動しない
- **`run` で守ること**：値は引数にもファイルにも置かず、受け取ったらすぐ `exec`。エラーやデバッグの出力にも値を出さない。値はリクエスト1回限り
  - 値を受け取ったら、`exec` の前に門番へのソケットを閉じる（開いたままだと、注入先のコマンドが門番への接続を引き継ぐ。Go の `net` は初めから close-on-exec だが、それに頼らず明示して閉じる）
  - 門番に送ったコマンドの絶対パスを、そのまま `exec` する（送ったものと違うものを動かさない）

### 結果：ソケットの相手の uid（2026-11-10）

- go1.27.3、`golang.org/x/sys` v0.50.0、作業用のフォルダ（リポジトリの外）で試した

## 作る順番

1. **骨組み**：`monban` という1つのバイナリに、`daemon`・`run`・`approve`・`deny`・`stop` の入口だけ作る。中身は空
   - 2026-11-10 に作った（`cmd/monban`）。どの入口も「まだ作っていない」で終わる
2. **ソケット**：`daemon` がソケットを開き、`run` が繋いで、相手の uid を取る。持ち主の uid と照合し、違えば断る
   - 2026-11-10 に作った（`cmd/monban/daemon.go`・`run.go`）。`daemon -socket <パス> -owner-uid <uid>`、`run` は環境変数 `MONBAN_SOCKET` で置き場を変えられる
   - 起動時に調べて、違えば起動しない：置き場がディレクトリで（シンボリックリンク不可）自分の持ち物で 0750、ソケットの場所に別のものがない、できたソケットが自分の持ち物で 0660・グループがディレクトリと同じ、パスが 103 バイト以内（macOS の上限）
   - ソケットは umask を先に絞って、作った瞬間から 0660 にする。止めると消す
   - 同じユーザーの中で確かめた：持ち主の uid を別にすると断り、自分にすると通す。ログに uid と pid が出る
   - 2026-11-10 に人のターミナルで、`nobody` から繋いで確かめた（置き場は `/tmp` の下、門番は自分の uid で動かした）
     - 自分（対照）：通した。ログは `uid=501`
     - `nobody`・ディレクトリのグループの外：`connect: permission denied`。門番まで届かず、ログにも出ない（0750 で止まる）
     - `nobody`・グループを `nobody` に替えた後：繋がったが断った。ログは `uid=4294967294`（`nobody` の -2）と pid
     - 別ユーザーの uid がカーネルから正しく取れること、壁が2枚（ディレクトリの権限と uid の照合）あることを確かめた
   - これで防げないこと：同じ uid のエージェントは `MONBAN_SOCKET` を偽の門番に向けられる（偽物は秘密を持っていないが、要求の中身は見られる）。ディレクトリのグループに誰を入れるかは、門番からは確かめていない
3. **`bws`＋最小のログ**：`daemon` が `bws secret get` を子プロセスで呼ぶ
   - `bws` は絶対パスで呼び、起動時に署名（TeamIdentifier `LTZ2PFU5D6`）を確かめる。合言葉は環境変数で渡す
   - 時刻・繋いできた uid と pid・申告されたエージェント名・秘密の名前・結果を、1行ずつファイルに足す
   - 2026-11-10 に作った（`cmd/monban/bws.go`・`secrets.go`・`audit.go`・`checks.go`）。`daemon` に `-bws`・`-token-file`・`-secrets`・`-log` を足した（どれも必須）。`run <秘密> -- <コマンド>` は秘密の名前と名札（環境変数 `MONBAN_AGENT`）を1行の JSON で送り、取れたかどうかだけを受け取る。値はまだ渡さない
   - 決めたこと：
     - **秘密の対応表**：`bws secret get` は ID でしか引けない。名前から引くのに `secret list` を呼ぶと、ほかの秘密の値まで全部門番に届くので、「名前 ID」の対応表のファイルを持つ。取れた秘密の名前（`key`）が対応表と違えば断る。4段目で許可リストにまとめる
     - **bws の置き場**：署名を確かめるのは起動時だけなので、確かめた後に差し替えられないよう、`bws` の本当の場所と上のディレクトリが全部 root か門番自身の持ち物で、グループとほかの人から書けないことも確かめる。本番（`_monban`）では `~/.local/bin` は通らないので、root の持ち物の場所に置く必要がある
     - 署名の条件：`anchor apple generic and identifier "bws" and certificate leaf[subject.OU] = "LTZ2PFU5D6"` を `/usr/bin/codesign --verify --strict` で確かめる
     - **bws に渡す環境変数**：`BWS_ACCESS_TOKEN` と `HOME` だけ。`HOME` は合言葉のディレクトリにする（`bws` の状態ファイルがその下にできる）
     - **ログ**：1行1つの JSON。名札は相手が決めるので、改行を混ぜても行を偽造できないよう JSON の文字列にする。名札と秘密の名前は 64 文字まで。ログに書けなければ断る。ファイルは自分の持ち物の 0600、シンボリックリンク不可
     - `bws` が失敗したときは、`stderr` の最初の段落（200 バイトまで）を門番の画面のログにだけ出す。ファイルのログには「bws が失敗」とだけ書く
     - 4段目で Muse に見てもらい、次を直した：対応表は許可リストにまとめた。`bws` の `HOME` は合言葉のディレクトリの下の `bws-home`（0700）にした。`stderr` は合言葉を伏せてから出す。本番（9段目）では生の `stderr` を出さず、失敗の分類と終了コードだけにする
   - 起動時に調べて、違えば起動しない：`bws` の署名と置き場、合言葉のディレクトリが自分の持ち物で 0700・ファイルが 0600（シンボリックリンク不可）、対応表の置き場が root か自分しか書けない・中身の形、ログのファイル
   - 偽の合言葉（ダミーの文字列）で確かめた：偽の `bws`（`/bin/ls`）・合言葉のファイルが 0644・ディレクトリが 0755・対応表がほかから書ける・対応表が壊れている・ログがシンボリックリンク、どれも起動しない。対応表にない秘密と、読めない要求は断り、`bws` の失敗も断る。どれもログに1行残る。名札に改行を入れても1行のまま
   - 2026-11-10 に人のターミナルで、本物の合言葉（試用の `mac-trial`）で確かめた（置き場は `/tmp` の下、門番は自分の uid で動かした）
     - `run MONBAN_TEST`：`取れた（値はまだ渡さない）`。`bws` から実際に取れた
     - `run NOPE`：`対応表にない秘密` で断った
     - `MONBAN_TEST` の値と合言葉を `grep -c -F` で探すと、`audit.log` にも門番の画面のログにも0件（空の文字列で探すと全部の行に当たるので、0件なら探す文字列は空ではない）
     - `audit.log` は2行。どちらも時刻・`uid=501`・pid・名札 `human`・秘密の名前・結果（`取れた`／`対応表にない秘密`）が入っていた。門番の画面のログも「待ち受け開始」「取れた」「断った」「止めた」の4行で、値は出ていない
   - これで防げないこと：
     - 合言葉は門番のメモリと、`bws` の子プロセスの環境変数にある。門番と同じ uid からは読める。今の試し方（自分の uid で動かす）では、同じ uid のエージェントから見える。本番は `_monban` で動かすので、ユーザーの uid からは見えないはず（10段目で確かめる）
     - ログは、門番と同じ uid なら書き換えられる（7段目まで）
     - `bws` のエラーの出力に値や合言葉が出ないことは確かめていない（出力の形を信じている）
     - 取り出した値は Go の文字列なので、使った後にメモリから消してはいない
4. **許可リスト**：どの秘密を、どのコマンドに、どの名札に渡してよいか
   - 2026-11-10 に作った（`cmd/monban/allowlist.go`）。`daemon` の `-secrets` を `-allowlist` に替えた。`run <秘密> -- <コマンド> [引数…]` は、コマンドを `PATH` から引いて絶対パスにし、`{"agent","secret","command":[絶対パス, 引数…]}` を送る。値はまだ渡さない
   - 大事な前提：**コマンドも名札も申告**。同じ uid のエージェントは、`run` を使わずにソケットへ直接書けば、許可されたコマンドを名乗って通れる。だからこの段の照合は、事故防止（うっかり別のコマンドやエージェントに渡すのを止める）と、ログと承認の材料。悪意のあるエージェントへの守りではない
   - 許可リストの形（JSON。例の ID は作り物）：

     ```json
     {
       "secrets": [
         {
           "name": "MONBAN_TEST",
           "id": "00000000-0000-0000-0000-000000000000",
           "allow": [
             {"command": "/usr/bin/printenv", "agents": ["*"]},
             {"command": "/usr/bin/curl", "agents": ["claude"], "hosts": ["api.example.com"]},
             {"command": "/opt/homebrew/bin/gh", "agents": ["human"], "userOwned": true}
           ]
         }
       ]
     }
     ```

   - 決めたこと（Muse と相談して）：
     - **照合**：コマンドは絶対パスの完全一致。名札は一致か `"*"`（だれでも）。名札は認証ではないが、「この秘密は Codex には渡さない」のような人の意図を書ける
     - **送り先のホスト**（`hosts`）：`curl` のように、どこへでも送れるコマンドにだけ付ける例外。付けたときは、`://` を含む引数（`--url=…` なら `=` の後ろ）を URL とみなし、https で、ホストが全部この中にあり、1つ以上あることを求める。URL に `ユーザー名@` があれば断る
     - **何でも実行できるコマンド**（`sh`・`bash`・`zsh`・`env`・`python`・`perl`・`ruby`・`node`・`osascript`・`xargs`・`find`・`sudo` など）は、門番の中の固定の一覧で断る。書かれていたら起動しない。書かれたパスと本当の場所の両方の名前で見る。スクリプトを動かしたいときは、そのスクリプトのファイルのパスを書く（スクリプトの中身は、書き換えられる人なら変えられる）
     - **コマンドの置き場**：`bws` と同じく、本当の場所と上のディレクトリが root か門番の持ち物で、グループとほかから書けないこと。書かれたパスのディレクトリも見る（シンボリックリンクの差し替えを防ぐ）。通らなければ起動しない
       - Homebrew など、ユーザーの持ち物の場所のコマンドは、項目に `"userOwned": true` を付けたときだけ許す。起動時の画面とログに「ユーザーの持ち物の場所のコマンドを許している」と出し、通した要求のログにも `user_owned` を付ける。6段目の承認の画面でも印を付ける
       - 置き場が厳しい確かめを通るのに印が付いていたら、起動しない（要らない緩さを残さない）
       - OS のもので足りるもの（`/usr/bin/curl`）は OS のものを使い、Homebrew にしかないもの（`gh` など）だけを例外にする
     - **ファイル**：JSON（Go の標準ライブラリで読め、要求とログと形が揃う）。知らない欄・名前や ID の重複・同じ秘密に同じコマンドが2回・後ろの余計なものは、起動しない。読み直すのは起動し直すときだけ
     - **持ち主**：本番は root の持ち物の 0644（門番が乗っ取られても、自分で許可を広げられない）。直すときは `sudo`。試すときは今の確かめ（root か自分の持ち物で、グループとほかから書けない）のまま
     - **断るときの返事**：理由を分けず、一律に `NG <リクエストの ID>`。詳しい理由は門番のログにだけ書く。`run` は「理由は門番のログを見てください」と出す。秘密の名前と組み合わせを総当たりで探られないように。6段目の承認でも「拒否」「時間切れ」は同じ `NG` にする
     - **ログ**：リクエストの ID、コマンドの絶対パス、引数の数、引数全体の SHA-256 を足した。引数の全文は書かない（別の秘密が入りうる）。承認の画面（6段目）には全文を出し、今回の秘密の値と一致する部分は伏せる
   - 自分の uid・偽の合言葉（ダミーの文字列）で確かめた（2026-11-10）：
     - 単体の試験（`go test`）：許可リストの形の誤り24通りが通らない。照合17通り（名札・コマンド・ホスト・`@` 入りの URL・http・URL なし・`--url=`）が思ったとおり
     - 起動しない：許可リストに `/bin/zsh`、`/usr/bin/printenv` に要らない印、欄の書き間違い（`agent`）、ほかから書けるディレクトリのコマンド、許可リストがほかから書ける
     - 印を付けると、ほかから書けるディレクトリのコマンドでも起動し、画面とログに注意が1行ずつ出た
     - 断った：許可リストにない秘密、許可していないコマンド（`cat`）、許可していないホスト、許可していない名札（`codex` で `curl`）、ソケットへ直接 `/bin/sh` を名乗った要求。どれも返事は `NG <ID>` だけで、理由はログにだけあった
     - 許したもの（`printenv`、`claude` で `curl https://api.example.com/`）は `bws` まで届いた（偽の合言葉なので `bws` が失敗）
     - 合言葉の文字列を探すと、門番の画面のログにも `audit.log` にも0件
   - 2026-11-10 に人のターミナルで、本物の合言葉（試用の `mac-trial`）で確かめた（置き場は `/tmp` の下、門番は自分の uid で動かした。許可リストは `MONBAN_TEST` を `/usr/bin/printenv` に、名札 `human` にだけ許す1項目）
     - `human` が `printenv MONBAN_TEST`：`取れた（値はまだ渡さない）`。`bws` から実際に取れた
     - `human` が `cat /dev/null`・`codex` が `printenv`・`human` が `NOPE`：3つとも返事は `NG <ID>` だけで、同じ形だった
     - 門番の画面のログと `audit.log` には、理由が分かれて残った（`このコマンドには許していない`／`この名札には許していない`／`許可リストにない秘密`）。`audit.log` は4行で、どれも ID・名札・秘密の名前・コマンドの絶対パス・引数の数・引数のハッシュが入っていた
     - `MONBAN_TEST` の値と合言葉を `grep -c -F` で探すと、`audit.log` にも門番の画面のログにも0件
   - これで防げないこと：
     - コマンドも名札も申告。同じ uid のエージェントは、許可された組み合わせを名乗れば通る（値を受け取るのは5段目から）。本物の `run` かを確かめる強化は v1.5（[design.md](design.md)）
     - 本物の `run` からでも、許可したコマンドが値をどう使うかは止められない。`curl` の `hosts` も、`://` のないホスト名、プロキシや設定ファイルの指定、`curl` と Go で URL の読み方が違うところは見ていない
     - 何でも実行できるコマンドの一覧は網羅ではない（`git` や `make` も、設定しだいで何でも実行できる）
     - `userOwned` の項目は、ユーザーの uid（エージェントも）が中身を差し替えられる
     - 試すときは門番を自分の uid で動かすので、`/opt/homebrew` などの自分の持ち物も厳しい確かめを通る。ユーザーの持ち物の場所が断られるのは、本番（`_monban`）になってから
     - 引数のハッシュは、引数が推測しやすいもの（短い秘密など）なら、総当たりで戻せる
5. **注入**：`monban run MONBAN_TEST -- コマンド` で、値をそのコマンドのプロセスにだけ渡す。値は `daemon` から `run` へソケットで渡り、`run` が環境変数に入れて `exec` する
6. **承認**：ターミナルの `monban approve` / `deny`（事故防止）。Pushover で知らせる
7. **ログのハッシュ連鎖**：3の最小のログに足し、書き換えを見つけられるようにする
8. **キルスイッチ**：`monban stop` で門番を止め、合言葉の失効の手順を出す（失効しても最大1時間は読める、と書く）
9. **常駐化**：`_monban` ユーザーの作成、LaunchDaemon の plist、ディレクトリと権限、合言葉のファイルの配置、入れ方と消し方
10. **本番の形でもう一度確かめる**：launchd のデーモン・`_monban`・`bws` で、実験1（`ps eww` で合言葉が見えないか）をやり直す。見えるかどうかはバイナリの署名の性質にもよるので、自作の Go のバイナリでも確かめる

## これで防げないこと（v1）

- 5で `run` が受け取った値は、ユーザーの uid の中にある。注入先のコマンドの環境変数は、同じ uid から `ps eww` で見える。コマンドが値を出力すれば、エージェントの会話に残る（伏せる処理は v1.5）
- 許可リストのエージェント欄は名札で、認証ではない。ソケットでわかるのは uid まで
- ターミナルの承認コマンドは、同じユーザーのエージェントが真似できる。だから v1 は高リスクの秘密を扱わない
- エージェントが `sudo` を取れれば、全部守れない（モデルの外）
