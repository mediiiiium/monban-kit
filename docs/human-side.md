# 人の側：Bitwarden の個人金庫を普段使いにする

作成日: 2026-11-12
前提：[muse-note-two-vaults.md](muse-note-two-vaults.md)（人は個人金庫と自動入力で、門番は通さない）、README の「2つの置き場と振り分け」

## なぜ人の側も見直すか

- 始めは、エージェントに何を渡すかを決めるためだった。渡すものを分けるには、手元の秘密がどこに何があるかを先に見る必要があった
- 見てみると、iCloud の「パスワード」や Chrome のいくつものプロファイルに散らばっていた。散らばったままでは、エージェント用の秘密がどこに混ざっているか分からない
- それで、人のパスワードも Bitwarden の個人金庫に集めて見直し、エージェント用の秘密は Secrets Manager に分けることにした。門番を作ったことが、人のパスワードを見直すきっかけになった

## 決まり

- 人の側は Bitwarden を普通に使うだけ。プロジェクトとして残すのは、導入の手順と結果だけ
- 足す決まりは1つ：エージェントに渡すかもしれない秘密は、個人金庫に入れず Secrets Manager（組織 `monban`）に置く
- パスワードの書き出しファイル（CSV など）、マスターパスワード、リカバリーコードは、このリポジトリにも会話にも出さない。結果に書くのは「やった・やっていない」と、つまずいたところだけ
- 画面の名前はアプリの版で変わる。手順と違ったら、やった人が直す

## 手順

### 1. アカウントと2段階認証（済み）

- 2026-11-10 に済んだ（[first-secret-trial.md](first-secret-trial.md) の「準備」）。アカウントは Secrets Manager の無料版の登録から作り、同じアカウントに個人金庫がある。2段階認証は認証アプリ

### 2. リカバリーコードを金庫の外に置く（済み）

- 2段階認証の画面からリカバリーコードを出して控える
- 置き場は Bitwarden の外にする（金庫に入れると、金庫に入れないときに使えない）。紙に書いて手元に置く、など
- 2026-11-12 に済んだ（置き場はここに書かない）

### 3. Mac で自動入力を使う

- 普段使うブラウザに Bitwarden の拡張機能を入れ、ログインする
- 拡張機能の「設定」→「アカウントのセキュリティ」で、タイムアウトを決める。15分・ロックにした（「ブラウザ再起動時」のままだと、ブラウザを開いている間ずっと金庫が開いている）
- 生体認証（Touch ID）で解錠できるようにする。拡張機能だけではできず、Mac の Bitwarden デスクトップアプリが要る
  - デスクトップアプリは **Mac App Store 版**を入れる。Chrome の拡張機能から Touch ID を使えるのは App Store 版だけ（公式サイトから落とした版や Homebrew で入れた版は対象外。[Bitwarden の開発者向け文書](https://contributing.bitwarden.com/getting-started/clients/browser/biometric)）
  - アプリに同じアカウントでログインし、設定の「セキュリティ」で「Touch ID でロック解除」をオン、タイムアウトを15分・ロックにする
  - アプリの「アプリ設定 (すべてのアカウント)」で「DuckDuckGo ブラウザの統合を許可する」をオンにする。名前は DuckDuckGo だが、この版（2026-11 時点）では、これがブラウザとつなぐ窓口を開くスイッチだった。オフにすると Chrome ともつながらない。「ブラウザとの統合を許可する」という項目は、この版の画面には無かった
  - 拡張機能の「アカウントのセキュリティ」で「生体認証でロック解除」にチェックを入れる。アプリを入れる前に入れていたら、外して入れ直す
  - Chrome の「ネイティブ アプリとの通信」の許可は、拡張機能が最初から持っていたので聞かれなかった
- どこか1つのサイトで、自動入力でログインしてみる

つまずいたところ（2026-11-12〜13）
- 拡張機能の「生体認証でロック解除」が灰色で押せなかった。原因は、DuckDuckGo の項目をオフにしたことで、アプリ側の窓口が閉じていたこと。アプリの記録（`~/Library/Containers/com.bitwarden.desktop/Data/Library/Application Support/Bitwarden/app.log`）で、項目をオンにした時に「Native messaging server started」と Chrome の接続が出て、オフにした時に「IPC server cancelled」が出ていた。これで分かった

### 4. スマホで自動入力を使う

- アプリは「Bitwarden Password Manager」だけ入れ、ログインする。「Bitwarden Authenticator」（2段階認証のコードを出す別アプリ）は入れない。Bitwarden 自身の2段階認証のコードは、いまの認証アプリに置いたままにする（同じ所に置くと、スマホ1台をなくしたときに金庫にもコードにも届かなくなる）
- アプリの「設定」→「アカウントのセキュリティ」で、「Face ID でロック解除」をオン、セッションタイムアウトを15分・ロックにする。「Authenticator との同期を許可する」はオフのまま
- OS の自動入力の設定で Bitwarden を選ぶ（iPhone は「設定」→「一般」→「自動入力とパスワード」。Android は自動入力サービス）
  - iPhone の「パスワード」（iCloud キーチェーン）はオンのまま残した。パスキーと確認コードが「パスワード」にあり、パスキーは手でコピーできず、自動入力を通してしか使えないため。いまあるパスキーを全部 Bitwarden で作り直すのは、数が多くて見送った
  - 役割を分ける：パスワードは Bitwarden、いまあるパスキー・確認コード・Wi-Fi は「パスワード」。新しく作るパスキーは Bitwarden に保存してもよい
  - 「強力なパスワードを提案」はオフにした。オンだと、新しく作ったパスワードが「パスワード」の側に保存される。新しいパスワードは Bitwarden の「パス生成」で作る
- どこか1つのアプリかサイトで、自動入力でログインしてみる

### 5. ほかの置き場から移す（する場合だけ）

- 移す元：Chrome のパスワード、iCloud キーチェーン（「パスワード」アプリ）など
- 多くは CSV に書き出して、Bitwarden のウェブ金庫の読み込みで入れる
  - CSV は平文。このリポジトリの外の一時的な場所に置き、読み込んだらすぐ消す（ゴミ箱も空にする）
  - エージェントが動いている間に書き出さない。同じユーザーのエージェントは CSV を読める
- 移した後、元の置き場のパスワードを消すかは決めてから進める（両方に残すと、変えたときに片方が古くなる）
- 移すときに振り分ける：エージェントに渡すかもしれないもの（API キーなど）は個人金庫に入れず、Secrets Manager に置く

- 書き出しと読み込みの間、Claude Code（同じユーザーで動くエージェント）を開いたままだった。手順の「エージェントが動いている間に書き出さない」は守れていない。エージェントは CSV を探したり開いたりしていないが、読める状態ではあった

  - 書き出しから読み込みまで、Claude Code は閉じていた
  - CSV は読み込んだ後に消し、ゴミ箱も空にした（空にしたのは同じ日の振り分けの後）
- 175 件の振り分け（2026-11-13）：エージェントに渡すものは無かった。Secrets Manager に移したものは無い

  - 1つのプロファイルでは、「パスワードとパスキーを保存するか確認する」がオフで、「Bitwarden パスワードマネージャーにより制御されています」と出ていた。拡張機能が自動で止めていた。「自動ログイン」はオンだったので、オフにした。このプロファイルのインポートの説明は「このデバイスの Google パスワード マネージャー」で、Google アカウントのアドレスが出ない（パスワードはこの Mac にだけあり、Google アカウントには同期していないと読める。未確認）

  - その後、このプロファイルでも「Bitwarden パスワードマネージャーにより制御されています」に変わった（Bitwarden の拡張機能が入っている）。保存の確認と自動ログインはオフ

## 結果

- 1・2：済み（2026-11-10、2026-11-12）
- 3：済み（2026-11-13）。Chrome の拡張機能と Mac App Store 版のデスクトップアプリで、Touch ID で解錠でき、自動入力でログインできた。タイムアウトはどちらも15分・ロック
- 4：済み（2026-11-13）。iPhone で、Amazon のビジネスアカウントに、Bitwarden にあったパスキーと Face ID でログインできた（アプリでそのログインを開くと、パスキーの作成日が 2026-11-13 0:47。Mac で手順3をしていた頃に入ったもの）。タイムアウトは15分・ロック。「パスワード」の自動入力はパスキーと確認コードのために残した
- 5：途中（2026-11-13）。iCloud の「パスワード」から 586 件を読み込み、CSV は消した。振り分けでは、エージェントに渡すものは無かった。Chrome から 65 件を読み込み、CSV は消した。Chrome の分の振り分けでも、エージェントに渡すものは無かった。Chrome の2つ目のプロファイルから 175 件を読み込み、CSV は消した。175 件の振り分けでも、エージェントに渡すものは無かった。残りの1つのプロファイルは移さないことにした。Chrome の2つのプロファイルで、保存の確認と自動ログインをオフにした。元の置き場をどうするかと、重なりの整理はまだ
- 6：使用中（2026-11-13 から）

## これで防げないこと

- 個人金庫は、マスターパスワードで開けば全部見える。出し分けはできない
- 解錠中の金庫は、同じユーザーで動くエージェントから守れない前提で考える（ブラウザの拡張機能やアプリの中身を、同じ uid のプロセスが覗く道を確かめていない）。だからエージェント用の秘密は個人金庫に置かない
- Touch ID のために、開いた金庫の置き場がブラウザの拡張機能とデスクトップアプリの2つになった。どちらもタイムアウトは15分・ロックにしてある
- デスクトップアプリは、ブラウザとつなぐ窓口（`~/Library/Group Containers/LTZ2PFU5D6.com.bitwarden.desktop/s.bw`）を開いている。同じユーザーで動くエージェントがこの窓口に話しかけて何ができるかは確かめていない（アプリ側で、つないできた相手の確認や Touch ID が挟まると思うが、未確認）
- 2段階認証の認証アプリの端末とリカバリーコードを両方なくすと、アカウントに入れなくなる
- iPhone では自動入力の取得元が Bitwarden と「パスワード」の2つある。手順5で移した後も両方に同じパスワードが残ると、片方だけ変えたときにもう片方が古くなる（2026-11-13 時点で、586 件が両方にある）。Mac の Chrome も同じで、65 件と 175 件が Chrome と Bitwarden の両方にある。iCloud と Chrome に同じサイトがあれば、Bitwarden の中でも2件に分かれている
- 振り分けは検索と目視で済ませたが、検索がメモ欄の中を見るかは確かめていない。開発に使うサービス以外の項目のメモ欄に、エージェント用の秘密が貼ってあれば見落としている
- 移さなかった Chrome のプロファイル（残りの1つと、初めから移さないとした4つ）のパスワードは、振り分けていない。そこにエージェント用の秘密があっても、このやり方では見つからない
- Chrome から読み込んだ 65 件のうち、Cloudflare Pages のダッシュボード2件の合言葉は、エージェントに使わせたことがあるか確かめていない。使わせていれば、エージェント用の秘密が個人金庫にある
