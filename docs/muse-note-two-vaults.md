# Muse とのやり取りのメモ：2つの置き場（個人金庫と Secrets Manager）

作成日: 2026-11-11
きっかけ：README と design.md を読み直して、本人が「人の側はどうなっているのか」を確認したやり取りのまとめ。Muse の説明を本人が確認済み。

## 気づいたこと

- README の1行目「自分の複数デバイス、スクリプトやCI、AIエージェントまでを同じ門番が仲介する」は、スマホでのログインまで門番が仲介するように読める。design.md の構成（人は個人金庫＋自動入力で、門番は通さない）と食い違っているので、README を直す。
- 直す文の案（「同じ Bitwarden」という言い方は、同じサービスか同じ金庫か曖昧なので、置き場を明示する）：
  「人は Bitwarden の個人金庫と自動入力で、スクリプトや AI エージェントは門番（許可リスト・承認・キルスイッチ）を通して Secrets Manager から鍵を使う」
- 人の側の「自分の複数デバイス」は、個人金庫の同期で賄う、という対応も読み手に伝わるよう書く。

## 人の側は、Bitwarden を普通に使うだけ

- スマホや Mac のアプリと自動入力で、人がログインする。門番は通さない。
- 人の側にプロジェクトとして残るのは、導入の手順（アカウント、2段階認証、リカバリーコードの保管）だけ。
- 普通の使い方に足される決まりは1つだけ：エージェントに渡す可能性のある秘密は、個人金庫に入れず Secrets Manager（組織 monban）に置く。

## 2つの置き場の違い

| | 個人金庫（パスワードマネージャー） | Secrets Manager |
|---|---|---|
| 入れるもの | サイトのログイン情報（URL・ユーザー名・パスワード・ワンタイムコード） | 名前と値だけの秘密（APIキー・トークンなど） |
| 使うのは | 人（アプリ・拡張機能の自動入力） | 機械（マシンアカウント＋合言葉） |
| 出し分け | できない。マスターパスワードで開ければ全部見える | できる。プロジェクト単位・読むだけ、合言葉ごとに絞れる |
| 置くものの目安 | 自分がログインするもの | プログラム・エージェント・スクリプト・CI が使うもの |

分ける理由：エージェント用の秘密を個人金庫に入れると、渡す時に金庫ごと開ける形になる。Secrets Manager 側なら、漏れても被害はそのプロジェクトの中だけで、合言葉を止めれば締め出せる。

## 同じサービスに、人もエージェントもログインする場合

「同じサービスに両方ある」と「同じパスワードが両方にある」は別。優先順位は次のとおり。

1. エージェント用に別の資格情報（APIキーなど）を発行する。人のパスワードは個人金庫だけ、エージェント用は Secrets Manager。止める時はエージェント用だけ失効できる
2. 個人金庫のログインを Agent Access 経由で使わせる（ログインごとに人が承認。複製を作らない）
3. 同じパスワードを両方に入れるのは最後の手段（漏れた時の被害が人のログインに直結する。変更時に2か所直すことになる）
