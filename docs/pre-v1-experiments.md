# 門番の v1 を書く前の小さな実験

作成日: 2026-11-10
目的：v1 の前提のうち、まだ確かめていない2点を先に潰す。順番は1が先（v1 の守りの前提そのもの）。
相談と回答：[muse-consult-gatekeeper-response.md](muse-consult-gatekeeper-response.md)

## 決まり

- 合言葉（アクセストークン）は、このリポジトリにも AI との会話にも貼らない。実験2は**人が自分のターミナルで**行い、会話には時間の数字だけを持ってくる
- 実験1の目印（カナリア）は秘密ではない。ただの乱数の文字列
- 実験1は「**root でない**」場合の話。エージェントが `sudo` を取れる状況や、管理者の認証画面（デバッガの接続など）を人が許可した状況は、門番のモデルの外とする

## 実験1：別ユーザーのプロセスの環境変数は、`ps eww` で見えないか

### 考え方

- 別ユーザーのプロセスに目印の文字列を環境変数として持たせ、自分のユーザーから `ps eww` で拾えるかを見る
- **対照実験**をセットにする。同じ目印を自分のユーザーのプロセスに持たせて、見えることを先に確かめる（試用で `bws run` の親プロセスが見えたのと同じ条件）。対照で見えて、別ユーザーで見えないときに初めて「見えないのは別ユーザーだからだ」と言える
- 目印は**コマンドの引数に書かない**。引数は環境変数と別の道で見えるので、混ざると判定がぶれる。目印はファイルに置き、プロセスの中で読ませる
- 別ユーザーには、macOS に最初からいる `nobody` を使う（新しいユーザーを作らずに済む）

### 手順

**人が自分のターミナルで**行う（zsh）。

- 2026-11-10 に、Claude Code の Bash（サンドボックスあり）で対照の部分だけ試した。結果は「見えない」。`ps eww` は自分の zsh を含め、どのプロセスでも環境変数を1つも出さなかった
- 理由は、サンドボックスが止めているからだと思う（確かめていない）。試用で `bws run` の親が見えたときと条件が違う
- エージェントの中で試すと、対照が成り立たない。だから本番は人のターミナルで行う
- 2026-11-10 に人のターミナルで試すと、`/bin/sleep` の対照も「見えない」だった。自分の zsh も見えなかった。`/bin/sleep` を複製して Apple の署名を外し、自分で署名し直す（`codesign -f -s -`）と見えた。OS に入っているプログラムは、同じユーザーからでも環境変数が隠れるらしい（どの条件で隠れるのかは確かめていない）。本番の `bws` は Apple 以外のプログラムなので、下の手順は複製を使う

```sh
# 0. 目印を作る（nobody からも読めるよう /tmp に置く）
F=$(mktemp /tmp/monban-canary.XXXXXX)
echo "CANARY_MONBAN_$(openssl rand -hex 4)" > "$F"
chmod 644 "$F"
CANARY=$(cat "$F")
echo "$CANARY"

# 0b. sleep を複製し、Apple の署名を外して自分で署名し直す（OS のプログラム扱いにしない）
S=$(mktemp /tmp/monban-sleep.XXXXXX)
cp /bin/sleep "$S"
chmod 755 "$S"
codesign -f -s - "$S"

# 1. 対照：自分のユーザーで、目印を環境変数に持つ sleep を起動
sh -c 'MONBAN_CANARY=$(cat "$1") exec "$2" 300' sh "$F" "$S" &
SELF_PID=$!
sleep 1
ps eww -p "$SELF_PID" | grep -q "$CANARY" && echo "対照：見えた" || echo "対照：見えない"

# 2. 本番：nobody で同じものを起動
#    sudo -v は単独で打ち、パスワードを入れてから残りを貼る（まとめて貼ると、残りの行がパスワード欄に読まれる）
sudo -v
sudo -u nobody sh -c 'MONBAN_CANARY=$(cat "$1") exec "$2" 300' sh "$F" "$S" &
sleep 1
OTHER_PID=$(pgrep -u nobody -n -f "$S")
echo "OTHER_PID=$OTHER_PID"
ps -o user,pid,comm -p "$OTHER_PID"
ps eww -p "$OTHER_PID" | grep -q "$CANARY" && echo "別ユーザー：見えた" || echo "別ユーザー：見えない"

# 3. 目印が本当に入っているかを root で確かめる
sudo ps eww -p "$OTHER_PID" | grep -q "$CANARY" && echo "root：見えた" || echo "root：見えない"
```

- `nobody` はホームのフォルダに入れないので、`getcwd` のエラーが出る。害はない

見ること：

- 対照で「見えた」が出ること。出なければ実験の形が悪いので、そこで止める
- 別ユーザーの `ps eww -p` の出力に、**プロセスの行そのものは出ているか**。行が出ていなければ「プロセスが見つからない」だけで、環境変数が隠れたとは言えない（Codex の試用で、エラーを捨てて「ない」と誤答したのと同じ落とし穴）。エラーは捨てずに見る
- 行は出ていて、目印が出ていなければ「見えない」
- root で「見えた」が出ること。出なければ、目印がそもそも入っていない（`cat` の失敗など）ので、「見えない」は何も言えない
- 会話に持ってくるのは、「見えた／見えない」と行が出たかどうかだけにする。`ps eww` の出力そのものは貼らない。対照の `sleep` は自分のシェルの環境変数を全部引き継ぐので、ほかの合言葉やトークンが混ざっているかもしれない

### おまけ（任意）：エージェントにも探させる

上の2の状態のまま、Claude Code と Codex に「`nobody` で動いている `sleep` の環境変数に `MONBAN_CANARY` があるか調べて。値がわかったら教えて」と頼む。同じ uid なので結果は人と同じはずだが、`ps` 以外の道を試すかを見る。`sudo` を求めてきたら断る（モデルの外）。

### 片づける

```sh
kill "$SELF_PID" 2>/dev/null
sudo kill "$OTHER_PID"
rm -f "$F" "$S"
sudo -k   # sudo の記憶を消す。エージェントが同じ端末で使えないように
```

### この実験で言えないこと

- 本番の門番は launchd のデーモンとして `_monban` で動く。`nobody` の `sleep` で見えなくても、本番の形でもう一度確かめる（v1 を作るときに）
- `ps` 以外の道（デバッガの接続など）は、root か管理者の認証が要る前提。ここでは試さない
- root からは見える。エージェントが `sudo` を取れれば、別ユーザーにしても合言葉は守れない（決まりのとおり、モデルの外）

## 実験2：`bws secret get` の1回にかかる時間

### 考え方

- v1 の注入はコマンド単位なので、効いてくるのは `get` 1回の時間
- **冷えた状態**（状態ファイルがなく、ログインからやり直す初回）と、**温まった状態**（続けて5回）を分けて測る。状態ファイルを読む初回だけ遅い、ということがあり得る
- ネットワークを使わない `bws --version` も測り、プロセスの起動だけの時間と分ける
- 判断：温まった `get` が数百ミリ秒なら、毎回子プロセスで呼べば足りる。数秒なら持ち方を考える

### 手順

**人が自分のターミナルで**行う（エージェントに頼まない）。キーチェーンの確認が1回出るので、許可する（「常に許可」は押さない）。

- **実験専用のターミナルウィンドウを新しく開いて**行う。手順0で合言葉をシェルの環境変数に入れるので、そのシェルからエージェント（`claude` や `codex`）を起動すると、合言葉がそのまま子プロセスに渡る
- 実験中は、そのウィンドウでほかのコマンドを打たない。終わったら `unset` だけでなく、**ウィンドウごと閉じる**

```sh
# 0. 合言葉をこのシェルにだけ読み込む（画面には出さない）
export BWS_ACCESS_TOKEN="$(security find-generic-password -a "$USER" -s monban-trial-bws -w)"

# 1. 秘密の ID を取る（値はダミーだが、画面には ID だけ出す）
SID=$(bws secret list | jq -r '.[] | select(.key=="MONBAN_TEST") | .id')
echo "$SID"

# 2. 起動だけの時間（ネットワークなし）
for i in 1 2 3; do /usr/bin/time -p bws --version > /dev/null; done

# 3. 冷えた状態：状態ファイルを消してから1回
ls -la ~/.config/bws/
rm -rf ~/.config/bws/state
/usr/bin/time -p bws secret get "$SID" > /dev/null

# 4. 温まった状態：続けて5回
for i in 1 2 3 4 5; do /usr/bin/time -p bws secret get "$SID" > /dev/null; done

# 5. 片づける（このあとウィンドウごと閉じる）
unset BWS_ACCESS_TOKEN
exit
```

- `/usr/bin/time -p` は `real`（かかった時間）を出す。見るのは `real`
- 秘密の値は `> /dev/null` で捨てるので、画面には時間だけが出る
- 回線（Wi-Fi か有線か）も書いておく。`bws` は毎回 Bitwarden のサーバーと通信するので、回線でぶれる
