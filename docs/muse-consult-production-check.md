## 1. ここまでの進み

- 9段目（常駐化）まで作り、人のターミナルで確かめた。門番は `_monban`（uid 401）の launchd のデーモンとして、ダミーの合言葉で動いている
- 10段目は v1 の最後の段。本番の形のまま、実験1（`ps eww` で合言葉が見えないか）をやり直す。見えるかどうかはバイナリの署名の性質にもよるので、自作の Go のバイナリでも確かめる（v1-plan の10段目）
- 実験1でわかっていること：Apple のプログラム（`/bin/sleep`、zsh）は、同じユーザーからでも `ps eww` で環境変数が出ない。署名し直した複製では出た。別ユーザー（`nobody`）の複製は出なかった。root では出た

## 2. 案（production-check.md の要点）

### 2-1. 合言葉がどこにあるか（今の作り）

- 合言葉は `/var/db/monban/secret/token`（`_monban` の 0600、ディレクトリは 0700）。門番は起動のときに1回だけ読み、メモリに持つ。門番そのものの環境変数には入れない
- 環境変数に入るのは、取り出しのたびに起こす `bws` の子だけ（`cmd.Env` は `BWS_ACCESS_TOKEN` と `HOME` の2つだけ）。1回あたり1秒ほどで消える
- `bws` は Bitwarden Inc の Developer ID の署名（Apple のプログラムではない）。門番は `go build` の署名（adhoc のはず）

### 2-2. A：自作の Go のバイナリ（合言葉は使わない）

- 実験1と同じ形。`sleep` の代わりに Go で書いた sleep（`go build`）、`nobody` の代わりに `_monban`
- 対照（自分の uid）で目印が見え、`_monban` で見えず、root で見えるかを見る
- ねらい：Go のバイナリが Apple のプログラムと同じく環境変数が隠れる性質なら、B で「見えない」が出ても、別ユーザーだからとは言えない。それを先に潰す

### 2-3. B：本番の門番と本物の合言葉

- 入れ替え：許可リストの `id` を `MONBAN_TEST`（値はダミー）の本物の ID に直し、合言葉を本物にして（`MONBAN_TEST` だけに届くマシンアカウント）、`kickstart -k` で起動し直す
- B-2：門番そのもの。本人の uid から `BWS_ACCESS_TOKEN=` の行の数（0 のはず）。root から、launchd が渡す `XPC_SERVICE_NAME` などが見えるか（見えるはず。root の目が効いている確かめ）、`BWS_ACCESS_TOKEN=` がないか（0 のはず）
- B-3：取り出しの最中の `bws` の子。裏で見張り（`pgrep -u _monban -x bws` を `sleep` なしで回す。最長3分）を回し、その間に `monban run MONBAN_TEST -- /usr/bin/printenv MONBAN_TEST` をして、別のウィンドウで承認する。見張りは最初に見つけた子について、本人の uid と root（`sudo -n`）の `ps eww` を1回ずつ取り、「行が出たか」と「`BWS_ACCESS_TOKEN=` を含む行の数」だけを出して終わる
- 期待：本人の uid は行 1・合言葉 0、root は行 1・合言葉 1。root の行が 0（子が先に消えた）なら何も言えないので、もう一度
- 出すのは数だけ。`ps eww` の出力はシェルの変数に一瞬持つが、画面には出さず、すぐ `unset` する

### 2-4. 決まり

- B はエージェントのいない新しいウィンドウで人が行う。会話に持ってくるのは「見えた／見えない」と数だけ
- 承認の番号が出ている画面は、有効なうちは貼らない。終わったら `sudo -k`

## 3. 聞きたいこと

### 3-1. A と B の分け方

- A（Go のバイナリの性質を対照つきで見る）は要るか。B の root の確かめ（`XPC_SERVICE_NAME` が見える）だけで足りるか
- A は `sudo -u _monban` で動かすので、launchd のデーモンとは起こされ方が違う。それで「自作の Go のバイナリでも確かめる」の目的に合っているか

### 3-2. `bws` の子の捕まえ方

- `sleep` なしで `pgrep` を回す見張りでよいか。1秒ほどの子を取り逃すことや、`pgrep` と `ps` の間に子が消えることはありうる（root の行が 0 なら、やり直す形にした）
- もっと確実な道（例：`bws` を遅くする、別の観察のしかた）があるか。ただし本番の `bws` と門番には手を入れたくない

### 3-3. 画面に出すもの

- 「行が出たか」と「`BWS_ACCESS_TOKEN=` を含む行の数」だけにした。root の `ps eww` の出力（合言葉そのものが入っている）をシェルの変数に一瞬持つのは許せるか。もっと安全な形があるか（例：パイプで直接 `grep -c` に渡す。そのときは行の有無を別に取ることになり、2回の `ps` の間に子が消えうる）

### 3-4. `ps` 以外で、root なしで試す価値のある道

- 実験1と同じく、デバッガの接続など root か管理者の認証が要る道は試さない
- root なしで、本人の uid から試す価値があるものはあるか（例：合言葉のファイルを `cat` して「Permission denied」になるか、`launchctl print system/io.github.mediiiiium.monban` に何が出るか）。足すなら手順に入れる

### 3-5. 本物の合言葉を、確かめた後どうするか

- 案：門番は本物の合言葉のまま動かしておく（届くのは `MONBAN_TEST` だけ）。やめるときは `monban stop` で止め、出てくる手順で失効させる
- それとも、確かめたらすぐ失効させ、ダミーに戻すほうがよいか

### 3-6. 「これで防げないこと」

- production-check.md の4つ（root からは見える／`ps` の道だけ／`monban run` が受け取った値は本人の uid の中／1回の瞬間の確かめで、ずっと見えないことの証明ではない）で、言い過ぎも言い足りなさもないか
- 10段目が通ったら、README で「本番の形の確かめまで済んだ」と書いてよいか。v1 として何が言えて、何が言えないかの書き方

## 決まり（相談でも守る）

- 合言葉や本物のパスワードは、このリポジトリにも会話にも出さない
- 「見せない」の効果を盛らない
