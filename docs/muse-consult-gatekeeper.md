# Muse への相談：門番の実装をどう始めるか

作成日: 2026-11-10
読んでほしいもの：[design.md](design.md)（設計メモ）、[first-secret-trial.md](first-secret-trial.md)（手で通した結果）
回答：[muse-consult-gatekeeper-response.md](muse-consult-gatekeeper-response.md)（2026-11-10）

## ここまでやったこと

- Bitwarden のアカウントを作り、2段階認証（認証アプリ）を入れた
- Secrets Manager の無料版で、プロジェクト `monban-trial`、ダミーの秘密 `MONBAN_TEST`、読むだけのマシンアカウント `mac-trial`、7日で切れる合言葉（アクセストークン）を作った。合言葉は Mac のキーチェーンにだけ置いた
- `bws` v2.1.0 を GitHub のリリースから入れ、チェックサムを確かめた
- Claude Code と Codex の両方から、秘密を手で通した

## わかったこと

- **`bws` とキーチェーンだけでは、同じユーザーのエージェントから合言葉を守れない**
  - Claude Code：`security find-generic-password` で、確認なしに合言葉を取れた
  - Codex：サンドボックスの中では取れない。ただ、人が「外で実行」を許可すると取れる。承認画面に出るのは長いコマンドと Codex が書いた理由なので、漏れるかどうかを人が見抜くのは難しい
- 合言葉が取れれば、`bws secret list` でそのマシンアカウントの秘密が**値まで全部**出る
- `bws run` は秘密の値だけを子に渡し、合言葉は渡さない。ただ、親の `bws` の環境変数に残っていて、`ps eww` で覗ける
- キーチェーンの項目の「アクセス制御」から `security` を外すと、読むたびに Mac の確認が出る。最低限の承認にはなる。ただ、画面に出るのは「`security` が読む」だけで、どのエージェントが何のために読むかは出ない
- 無料枠はマシンアカウント3つ。エージェントごとには作れないので、**1台に1つ**にして、エージェントの見分けは門番の許可リストとログで行う。監査ログは有料なので、記録も門番が持つ

## 門番に最低限ほしいこと

1. 合言葉を門番だけが持つ。エージェントのプロセスから見えない場所に置く（別ユーザーなど）。`ps` でも覗けない
2. 許可リスト：どのエージェントが、どの秘密を読めるか
3. 承認画面に、門番が作った事実を出す（どのエージェント・どの秘密・何に使うか・コマンドのハッシュ）。承認は1回限りで短命
4. 誰がいつ何を読んだかのログ
5. キルスイッチ（全部止める）

## 考えている始め方（どれがよいか相談したい）

| 案 | 中身 | 気になること |
|---|---|---|
| A. mcp-warden に Secrets Manager 対応を足す | 一番成熟している（許可リスト・注入・時間枠つき承認・キルスイッチ）。金庫を足すだけ | 作者が受け入れるか。同じユーザーで動く前提なら、合言葉の置き場は解決しない |
| B. 薄い門番を自分で書く | Mac の別ユーザー（例 `_monban`）で常駐。合言葉はそのユーザーのキーチェーン。エージェントとは Unix ソケットでだけ話す。承認は通知かスマホ | 別ユーザーから Touch ID や通知を出せるか（未確認）。導入の手間 |
| C. R055LE/secrets-broker を Mac に移す | Secrets Manager を背後に置き、別ユーザー＋別デバイスで承認する設計がもうある | Linux 専用。移す手間が書く手間と変わらないかもしれない |

いまの気持ちは「B を最小で作り、A の設計（許可リストの書き方、時間枠つき承認）を借りる」。

## 聞きたいこと

1. A・B・C のどれから始めるのがよいか。別の案があれば
2. B にするなら、最初の版で何を削るか（例：承認は最初はターミナルの確認だけ、MCP は後回し）
3. 言語は何がよいか（Go、Rust、Python など）。`bws` を子プロセスで呼ぶか、SDK を直接使うか
4. 別ユーザーの門番から、ログイン中のユーザーに承認を出す方法（通知、Touch ID、スマホ）
5. エージェントへの渡し方は、環境変数の注入（設計メモの段 B）と代理実行（段 C）のどちらを先に作るか
6. この方針で見落としている穴があれば

## 決まり（相談でも守る）

- 合言葉や本物のパスワードは、このリポジトリにも会話にも出さない
- 「見せない」の効果を盛らない。同じユーザーで動く簡易モードは事故防止であって、隔離ではない
